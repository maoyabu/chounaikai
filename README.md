# 町内会管理システム

`accountbook_project_clean` と `menu-service` が利用するMongoDBの `users` / `groups`
を再利用し、町内会固有情報を専用コレクションで管理する独立アプリケーションです。

個人情報の保存先、検索・絞り込み機能、住所・電話番号の暗号化に向けた調査結果は
[個人情報の保存先・検索機能一覧](PERSONAL_DATA_INVENTORY.md) にまとめています。
住所・電話番号の暗号化に必要な鍵設定と、既存データの移行・本番反映手順は
[住所・電話番号の暗号化](PERSONAL_DATA_ENCRYPTION.md) を参照してください。鍵の設定とデータ移行を行ってから起動してください。

## 町内会の退会申請

プロフィールの「町内会の退会申請」から申請・確認ができます。家族は世帯主の承認後に班長へ送られます。世帯主は世帯全員の退会、または同じ世帯の参加中の会員を新しい世帯主に指定して本人だけの退会を選択します。いずれも現在年度の担当班長が班長メニューの「退会申請」で最終承認します。申請者は最終承認前に取り消せます。世帯単位で確認中の申請は1件のみです。

申請中は所属を維持し、班長の承認時に世帯主の切り替えと退会を確定します。退会時は対象者の所属・町内会権限・現在以降の役員／班長設定を終了し、町内会の共通グループからのみ外します。世帯全員の場合はアカウントを持たない子供なども含め家族の所属を終了し、世帯を非表示にします。共通アカウントや履歴、他サービスのグループは削除しません。世帯主や班、対象者の所属が申請後に変更された場合は取り消し・再申請が必要です。通知はアプリ内のお知らせに表示します。

## 安全上の境界

- 共通 `users` / `groups` に町内会固有フィールドを保存しません。
- 既存ユーザーのパスワードは `passport-local-mongoose` の既存形式で検証します。
- セッションCookieは `chounaikai.sid`、保存先は `chounaikai_sessions` です。
- 町内会退会とアカウント全体の `unsubscribe_date` は別操作です。
- 共通所属配列を更新するときは `$addToSet` / `$pull` のフィールド単位更新だけを使います。

## 起動

1. `.env.example` を参考に、コミット対象外の `.env` を作成します。
2. `npm install`
3. `npm test`
4. `npm start`

`MONGODB_URI` と `CHOUNAIKAI_SESSION_SECRET` が未設定の場合は起動しません。

新規会員登録の確認メールには `PUBLIC_BASE_URL`、`SMTP_HOST`、`SMTP_PORT`、
`SMTP_USER`、`SMTP_PASS`、`MAIL_FROM` の設定が必要です。設定前はユーザーを
仮登録せず、登録画面に準備中メッセージを表示します。
確認前の情報は町内会専用 `pending_user_registrations` に保存し、確認リンクが
開かれた時点で初めて共通 `users` に登録します。確認リンクは24時間有効です。

プロフィール写真の新規アップロード・差し替えは、所属町内会のGoogle Drive連携を使用します。
プロフィール画面で保存先の町内会を選択すると、起点フォルダ直下の「プロフィール写真」に保存されます。
既存サービスと共通の `users.avatar` には本サービスの画像配信URLを保存し、Driveのファイル自体は公開しません。
既に登録済みのCloudinary等の写真はそのまま表示され、差し替えるまで自動移行しません。
Google Drive連携が未設定でも写真以外のプロフィール更新は利用できます。

既存データの読み取り専用事前監査は `npm run audit:legacy` で実行できます。
このコマンドは件数と参照不整合の集計だけを行い、ドキュメントを変更しません。

## 現段階のAPI

- `GET /health`
- `GET /login`
- `GET /register`
- `POST /api/auth/login`
- `POST /api/auth/logout`
- `GET /api/auth/me`
- `GET /api/associations`
- `POST /api/associations`
- `GET /api/associations/:associationId`
- `POST /api/associations/:associationId/approve`（システム管理者）
- `DELETE /api/associations/:associationId?mode=hidden|permanent`（システム管理者）
- `POST /api/associations/:associationId/restore`（システム管理者・非表示解除）

一般ユーザーによる町内会作成は承認待ちの申請として保存されます。システム管理者が
承認した時点で公開し、申請者の所属と「町内会管理者」ロールを同時に作成します。
削除は、監査履歴とデータを保持する非表示削除と、関連データを消去する完全削除を選べます。
承認と参加承認は、専用コレクションと既存の双方向所属配列を同期します。
レプリカセットまたはmongosではMongoDBトランザクションを使います。単体MongoDBでは
フィールド単位の原子的更新を使い、途中失敗時はそのリクエストで作成したIDだけを取り消します。

町内会管理者は `/associations/:associationId/manage` から、基本設定と年度設定へ進みます。
基本設定は役職、部会、班、町内会名を管理します。年度設定は住人から年度役員を選定し、
役職・所属部と年度別班長を管理します。班長を指定するとアプリ内通知が作成されます。
役職・部会・班には表示順を設定でき、基本設定の各行をドラッグ＆ドロップして移動できます。
世帯代表者は町内会と班を選んで世帯情報を登録し、参加申請を行います。現在年度の班長は
`/associations/:associationId/leader` から自分の班への申請を承認・拒否し、班員情報を閲覧できます。
拒否理由と審査結果は申請者へアプリ内通知されます。

## 家族のアカウントと世帯への参加

- アカウントを持たない子どもなどは、従来どおり世帯主がプロフィールの「世帯情報」で管理します。
- 世帯主は登録済みの未紐付けの家族から、本人のメールアドレスへ招待を送れます。
  招待から新規登録（メール確認あり）、または既存アカウントでログインし、受諾すると
  同じ家族に紐付き、班長・町内会管理者の承認待ちになります。
- 町内会への参加申請は世帯主が行います。参加後、プロフィールの「世帯情報」で家族を
  登録し、利用する家族には本人のメールアドレスへ招待を送ります。
- 家族は招待メールから会員登録またはログインして受諾します。招待先のメールアドレスで
  家族に紐付き、班長または町内会管理者の承認後に町内会を利用できます。
- 町内会管理者は運営管理の「参加申請」から招待元や世帯主の確認状況を確認して承認できます。
  承認前は町内会の所属・機能利用権限を付与しません。
- 世帯主だけが世帯全体を管理します。アカウントに紐付いた家族は、自分の本人情報だけを
  プロフィールから変更でき、他の家族の個人情報を編集できません。

招待には既存のSMTP設定を使います。`PUBLIC_BASE_URL` は招待される人が開けるURLに
設定してください。招待は7日間有効で、トークンはハッシュだけを保存します。
町内会参加の登録動線情報は、共通 `users` ではなく町内会専用
`resident_registrations` と `pending_user_registrations` に保存します。

## 班長による世帯削除

班長メニューの「班のメンバー」で、各世帯の「世帯を削除」から確認画面を開きます。
世帯主・住所・家族と影響範囲を確認し、確認チェックを入れてから削除を確定します。
今年度の担当班以外の世帯は、確認画面の表示時も削除の確定時も操作できません。
確認は10分間有効で、その間に対象データが変わった場合は確認画面の開き直しが必要です。

削除は論理削除です。世帯情報を非表示にし、紐付いた会員の町内会所属を無効化して、
未完了の招待・参加申請を取り消します。該当会員の管理権限と今年度以降の役員・班長も
無効化します。共通アカウント、他のグループの所属、家族情報、過年度の役員・班長、
監査履歴は保持します。処理途中の失敗時はトランザクション、または対象を限定した
取り消し処理で元の状態に戻します。データの完全削除や復元用の画面は設けていません。
# パスワードの再設定

ログイン画面の「パスワードを忘れた方」から、登録済みメールアドレスへ再設定リンクを送信できます。既存のSMTP設定とPUBLIC_BASE_URLを使用します。リンクは1時間・1回限り有効で、トークンは専用のpassword_resetsコレクションにSHA-256ハッシュで保存します。再送は同一アカウントにつき1分間隔です。共通usersコレクションのsalt/hashのみを更新するため、共通アカウントを利用する他サービスのパスワードも変更されます。

## Google Driveドキュメント管理

町内会管理の「Google Drive連携設定」に各町内会のOAuthクライアントと共有フォルダを登録します。役員メニューの「町内会ドキュメント管理」から資料を操作できます。サーバーには `DRIVE_ENCRYPTION_KEY` と公開URLの設定が必要です。設定・Google審査・対応形式は [GOOGLE_DRIVE.md](GOOGLE_DRIVE.md)、管理者向けの1枚資料は [準備手順PowerPoint](src/public/documents/google-drive-setup.pptx) を参照してください。

## 本番セキュリティ設定

認証関連のレート制限、Helmet、HTTPS強制・HSTS、本番MongoDBの認証・TLS検証を適用します。
本番は `PUBLIC_BASE_URL` にHTTPS origin、`MONGODB_ALLOWED_HOSTS` にAtlasの接続先ホストを設定する必要があります。
Herokuでは `TRUST_PROXY=1` を使用します。設定不足や安全でないMongoDB接続では起動しません。

Atlasの接続元制限には固定IPの確保とNetwork Access設定が別途必要です。
固定IP用SOCKS5プロキシは `FIXIE_SOCKS_HOST` または `MONGODB_SOCKS_PROXY_URL` に設定します。
導入・検証手順と制限値は [SECURITY.md](SECURITY.md) を参照してください。

## 管理者の多要素認証

初期設定では、システム管理者と有効な町内会管理者権限を持つアカウントに認証アプリによる追加認証が必須です。システム管理者のダッシュボードの「サイトの多要素認証設定」で、このサイト全体の使用する／しないを切り替えられます。切り替えにはパスワード確認、登録済みの場合は追加認証も必要です。
初回はQRコードで設定し、以後は6桁コードを入力します。紛失時用の一度だけ使える復旧コードも発行します。
共通usersにはMFA項目を追加せず、町内会専用の暗号化された保存先を使用します。

**本番反映前にMFA_ENCRYPTION_KEY（64桁のランダムな16進文字列）を設定してください。未設定では本番起動しません。**
利用と反映・検証の手順は [MFA.md](MFA.md) を参照してください。

## 個人情報の閲覧監査

システム管理者のダッシュボードから「個人情報の閲覧監査ログ」を確認できます。住人・世帯・役員・連絡・文書などの表示と出力を記録し、保存失敗時は対象情報を返しません。対象機能、検索方法、保管とテストは [PRIVACY_AUDIT.md](PRIVACY_AUDIT.md) を参照してください。

### 緊急・危険情報

参加中の住人は、各画面右下の「＋」から写真・タイトル・内容を投稿できます。写真選択時にJPEG/PNG/WebPのEXIF位置情報を読み取り、含まれない場合は端末の現在地を取得します。ブラウザや写真共有時に位置情報が削除される場合は、現在地の利用許可が必要です。GPS取得に失敗した場合はネットワーク位置情報・直近1分以内の位置情報でも再試行します。写真の撮影場所と端末の現在地は取得元を分けて記録し、写真の位置精度は不明として扱います。本番ではHTTPSを使用してください。スマホのカメラ起動はブラウザの対応によって異なります。写真はJPEG/PNG/WebP形式、10MB以下の1枚を設定済みGoogle Driveの「メッセージ添付フォルダ」に自動保存し、所属町内会の有効なメンバーだけに配信します。投稿者と投稿日時はサーバーで記録します。

ホームには日本時間の当日・前日の投稿がある場合だけ、その期間の最新6件を濃い赤の背景で表示し、詳細にGoogleマップと内容を表示します。町内会別の地図・履歴は50件ずつ閲覧できます。地図はAPIキー不要の埋め込み表示を使い、写真をタップするとその投稿の場所へ切り替わります。住所入力の投稿は住所・場所の検索結果を表示します。タイトルから投稿詳細を開けます。

Danger report photos use the association Google Drive connection and automatically create the message attachments folder when needed. A failed report save rolls back the uploaded file. Existing database photos migrate to Drive when first viewed; database image data is removed only after the Drive reference is saved.

緊急・危険情報は詳細画面から、所属町内会の現任役員または町内会管理者が確認後に削除できます。削除時はサーバーで権限を再確認し、Google Driveの写真も削除します。Driveの写真削除に失敗した場合はその旨を表示します。

### わがまちのいいところ

所属町内会の住人はハンバーガーメニューの「ホーム」の下にある「いいところ投稿」から、写真（撮影・アルバム）、タイトル、内容を投稿できます。緊急・危険情報と同じ位置情報取得・EXIF読み取り・住所入力、10MB以下の写真制限を使います。写真は設定済みGoogle Driveのメッセージ添付フォルダに自動保存します。

投稿は写真・タイトル・内容・投稿日時・場所を町内会PRページで一般公開します。公開PRページでは投稿者氏名を表示せず、所属町内会の有効な住人が見るページのみに氏名を表示します。詳細・履歴でも同じルールを適用し、未ログイン・他町内会の利用者には投稿者情報を渡しません。PRページの行事カレンダーの上に、写真枚数に応じたギャラリーを表示し、詳細には内容・Googleマップ・地図と履歴へのリンクを表示します。履歴は50件ずつ閲覧でき、写真をタップして表示場所を切り替えます。APIキーや有料地図APIは使用しません。

投稿時は町内会の有効なメンバー全員へアプリ内のお知らせを作成し、既存の配信処理でWeb Push・メール通知を送ります。初期設定は両方ONで、町内会の通知設定で変更できます。SMTP/VAPIDの設定と受信者の通知許可・メールアドレスが必要です。役員・町内会管理者は詳細画面から投稿とDriveの写真を削除できます。

いいところの写真は、1枚なら大きく1枚、2枚なら1枚ずつ切り替え、3枚なら最新を大きく残り2枚を小さく表示します。4枚は同じ3枠を切り替え、5枚以上は大1枚＋小4枚を切り替えます。PCは左右、スマホは上下に配置します。自動切り替えは6秒ごとで、前後・一時停止操作、マウスやキーボードでの操作中の停止、動きを減らす端末設定に対応しています。

いいところの投稿完了・削除後は、その町内会の公開PRページへ戻ります。ギャラリーの写真は約0.8秒のクロスディゾルブで切り替わり、動きを減らす端末設定では即時に切り替えます。

いいところの詳細ページでは、所属町内会の有効な住人がLike（1人1件・取消可能）とコメント（1000文字以内）を投稿できます。公開閲覧者や他町内会の利用者にはLike・コメント欄を表示しません。投稿時のコメント受付は初期設定で「コメントあり」で、「コメントなし」を選ぶとサーバーでもコメント投稿を拒否します。既存投稿はコメントありとして扱います。投稿者本人はコメントを非表示・再表示でき、非表示のコメントは投稿者以外には表示されません。コメントは50件ずつ閲覧できます。
